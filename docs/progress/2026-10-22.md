## Ollama 0.33.2 → 0.40.8

**Before the upgrade.** The release notes from 0.33.3 to 0.40.8 were reviewed. Three points mattered:

- 0.40.0–0.40.2 migrated legacy GGUF manifests in the background, which would rewrite pinned digests. 0.40.3 turned the migration off.
- From 0.40.0, Apple Silicon prefers MLX for architectures it supports, gemma4 included, but only for models that have an MLX manifest.
- No environment variable was removed or changed meaning.

A baseline was saved first: `/api/tags`, `/api/show` for the three production refs, and a copy of the legacy manifests.

**Upgrade.** The maintainer ran `HOMEBREW_NO_INSTALL_CLEANUP=1 brew upgrade ollama`, so the 0.33.2 Cellar is kept for rollback, then restarted the daemon. The new version answered at 07:17:27 UTC. With no operator action, the residency reconciler restored gemma4 at 07:18:59 and the embedder at 07:19:03. Every capability was available again at 07:19:52.

## #68 §1 and §4: two maintainer decisions

**§1 (R6) is accepted as it behaves.** A repeat cannot tell a lost forward from
a slow one. A copy that arrives after the original is bound, but before its
forward reaches the agent, tombstones the bound attempt (`cancelled_unsent`)
and takes the request over. The original's late forward only observes the
tombstone, so its caller gets an error instead of the shared result. Nothing
runs or is billed twice. The comments that promised a duplicate would
"converge" on the original now say this. The integration test that pins the
path now names the concurrent case too.

**§4: widening needs a declared capacity.** The gateway drops Ollama's half
window only for a validated profile. When that measurement declared no
context, it used to widen to the registered `context_length`. It now keeps the
half, so a prompt past it is refused with `ContextTooLongError`, and logs why.
The agent already refused anything past what it admitted, so this moves the
refusal to the gateway rather than closing a hole.
