## Compact before refusal and preserve grounded prefixes (#51, #52)

Implemented by **review-codex** against the final inference specification on
issue #24. These changes are proposed for review; they have not been deployed.

Compaction now uses the smaller of the deployment input ceiling and the selected
target's own admission budget. Legacy and validated-profile admission retain
their existing output reserve and truncation backstop, and the final guard runs
after recounting the transformed prompt. Compaction-enabled keys can attempt
the floor-over-cap path behind an 8 MiB serialized-prompt bound and a 120-second
transformation deadline. Disabled keys retain the early floor refusal. Tier 1
cuts on stable ten-message boundaries.

Tier 2 sends a summary operation to the selected assist model's node agent.
The agent owns one outstanding summary per node, backed by durable operations,
and refuses a second summary with 503 and Retry-After before counting it.
Cache hits bypass that slot. Summaries require an exact counter and known
capacity, and have separate byte, token and time limits. An uncertain summary
blocks node dispatch until terminal evidence or audited resolution.

Model registrations and edits reject context above the selected host's declared
capacity. A persisted capacity_validated flag starts false until metadata is
read; empirical profile validation remains separate. Unresolved inference
capacity fails closed, and the gateway and agent apply the same three-times
estimate reserve. Native preparation avoids building a redundant Python
vocabulary, Responses collection joins fragments, and equivalent source line
endings retain the same counting fingerprint.

Grounding stores canonical context and citations in immutable, bounded full
anchor chains. Server-keyed canonical HMACs identify records and their 128-bit
fences. Concurrent contenders replay the Redis SET NX winner. PostgreSQL
tenant and collection epochs fence mutations, including index publication;
only the same clean epoch permits recording and replay. Begin commits before
side effects, and request End is published with the content transaction.
Failed or rolled-back mutations remain dirty until audited recovery.

Embedding identity includes the runtime, reference and exact manifest. Every
batch carries the expected manifest to the node, which checks it before
admission and again at runtime dispatch. Existing indexes of unknown provenance
require a complete tenant rebuild before adopting an identity. The migration
does not infer provenance from the current routing policy. Operational bounds
and recovery steps are in [grounding-records.md](../runbooks/grounding-records.md).

Independent Agents reviewed correctness, regression behavior, tests and
architecture/security. Review fixes covered inconsistent estimate budgets,
delayed summary overload refusals, legacy-space adoption, manifest transport,
bounded cache lookup and epoch lock ordering. Final reviews found no remaining
blocking findings. Validation results are recorded in the pull request.

Live Ollama/GPU timing and whole-runtime token agreement were not run on this
Windows host. The grounding prefix regression uses the actual sandboxed prompt
renderer and real byte-level BPE token IDs; it establishes structural prefix
invariance without claiming a runtime benchmark.
