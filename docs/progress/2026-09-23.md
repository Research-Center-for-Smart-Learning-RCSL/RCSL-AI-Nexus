## `MetricsPort` 接上了：live host memory 進入 model-load budget check

`485c189`。`MetricsPort` protocol 在 `domain/ports/infrastructure_ports.py`，
`HttpMetricsAdapter` 在 `adapters/http/metrics_port.py`。adapter 透過共用的
`fetch_host_metrics()` 打 `host.docker.internal:9101/host`，取
`memory.available_gb`。

DI 裡接了兩處：

- `infrastructure/di/inference_runtime.py` 把 `HttpMetricsAdapter` 傳進
  `ManageModels`，`lifecycle.py` 的 `load()` 在取得 routing target 之後呼叫
  `self._metrics.free_memory_gb(node.id)` 並傳進 `assert_can_load(live_free_gb=...)`
- `infrastructure/di/admin_observability.py` 把同一個 adapter 傳進 `ReadDashboard`

`MemoryBudgetService.assert_can_load` 先跑 static check（跟以前一樣），再跑
live check：如果 host 的 available memory 比 model 需要的少，就算 static budget
說得下也拒絕。`None`（agent 不可達）退回 static check alone。

`test_memory_budget.py` 裡 10 個測試涵蓋 live free memory 的拒絕、允許、
None fallback 和 static-refuses-before-live 的順序。

同一個 commit 也更新了 `MemoryBudgetService` 的 module docstring，記錄
`observed_memory_gb` 是 floor 不是 replacement 的原因（2026-09-07 修正的）。
