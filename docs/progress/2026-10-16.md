# 2026-10-16

## PR #56 availability and rollout review

Addressed the October 16 review of context compaction and grounded-prefix
replay. The caller's 30-second summary wait is separate from the agent's owned
drain. A local deadline discards output and settles failed after runtime
terminal evidence; it no longer manufactures a node-blocking unknown. Actual
transport loss still preserves the uncertainty contract.

Legacy knowledge indexes continue live retrieval and accept uploads/re-indexes.
Their migration flag now marks unverified provenance and disables immutable
replay only. Dirty mutation fences also disable recording/replay only. Added an
audited offline recovery CLI with an expected-epoch check, tenant-scoped active
administrator identity, explicit writer-quiescence acknowledgement, and a full
tenant rebuild path. Rebuild preflights stored text, drops the entire tenant
vector index, pins every embedding batch, and only clears provenance/fences
after complete publication. Interrupted rebuilds remain separately marked and
must resume through the rebuild command. See the
[runbook](../runbooks/grounding-records.md) for commands and operational limits.

Capacity metadata is cached per node/ref/registered manifest for 60 seconds;
agent admission remains authoritative. Pinned embeddings negotiate agent
support before sending. Grounding record admission is atomic with per-tenant
and global quotas, preserving existing prefixes when full. Model loads update
capacity with a conditional column write instead of restoring a stale model
snapshot over a newer administrative edit or observation.

The rollout explicitly requires agents before gateways. Unresolved capacity,
zero-context registrations and MLX without declared metadata remain refused;
direct-MLX installations must defer this rollout. The conservative estimate
budget and domain-separated API-key pepper remain documented decisions.

Integrated main after #60 merged and chained the capacity migration onto
`b9e2d74a6f31`, leaving one Alembic head. Regression coverage includes local
deadline drain, caller departure, genuine transport uncertainty, Tier 2 through
the agent and synthetic Ollama wire protocol, live dirty/legacy retrieval,
legacy publication, recovery/audit rollback, interrupted rebuild, Redis quota
contention/expiry, and delayed model-capacity writes. No deployment or live GPU
timing measurement was performed.

Local validation passed the full Linux unit suite (1,371 passed, 71 skipped),
then the Qdrant adapter suite including two new reset tests (21 passed). The
full PostgreSQL 17 / Redis 7 integration suite passed all 223 tests. Ruff
lint/format and strict mypy passed (385 source files). Frontend TypeScript,
ESLint and the two logs test files passed (5 tests); the generated audit action
catalogue was refreshed. Skipped unit cases and synthetic runtime tests are not
claimed as live GPU validation.

The follow-up review confirmed the three P1 fixes and identified quota
exhaustion as a remaining blocker. Full tenant/global quotas now retain any
stored prefix and use fresh current-turn context/citations without recording;
a content-free warning identifies the degradation. Long conversations that
outlive the retained lookup window also use fresh grounding. Regression cases
cover follow-ups and retries, new conversations under both quota limits,
bounded cold lookup, and epoch changes before the fallback returns. The four
non-blocking follow-ups from the review remain outside this correction.
