## Attempt billing after an unsent retry (#32)

Selected the request-binding and exactly-once usage review in the remote
watch list, [#32](https://github.com/Research-Center-for-Smart-Learning-RCSL/RCSL-AI-Nexus/issues/32).
Open PRs #56-#59 cover compaction, grounding, residency, availability,
lifecycle uncertainty and Jev feasibility; none addresses this retry defect.
The review is based on main `cb6f32c` and does not claim to complete the
watch list's other review items.

A binding that never reached its agent can be tombstoned as `cancelled_unsent`
and rebound to a new attempt. The new route and generation were used, but the
original binding's model, start time and compaction snapshot still supplied
usage settlement and replay. A real PostgreSQL/ASGI reproduction showed a
completed retry retaining the old model reference instead of `qwen2.5:7b`.

Each newly inserted attempt now stores its own billing snapshot. The versioned
rebind and snapshot insertion share one transaction, and racing contenders
read the winner. Settlement and replay use the selected attempt's snapshot;
the original request snapshot and each earlier attempt remain immutable.
Gateway grants remain limited to inserting snapshots and updating binding
versions and delivery evidence.

The additive migration must precede application rollout. Its nullable column
allows legacy attempts and older gateways to retain the original binding
snapshot as a read fallback. Historical per-attempt facts cannot be recovered,
so existing usage is not rewritten. Roll back applications before dropping
the column. If another pending PR extends the same Alembic head first, rebase
this migration onto that head before merging.

PostgreSQL acceptance covers changed routing/time/compaction, one execution
and usage row on replay, three racing rebinds, failed-insert rollback, legacy
INSERT/read/settlement, migration downgrade/upgrade with existing data, and
denied gateway UPDATEs to both snapshot columns. The new retry reproduction
failed before the fix. The full Linux unit suite passed 1,283 tests with 71
skipped cases; all 23 focused PostgreSQL integration cases passed. Strict
Linux mypy passed all 378 application files; full backend Ruff lint and format
checks and 548 documentation links passed. Windows CRLF conversion initially changed the tokenizer source
fingerprint; exporting with `core.autocrlf=false` reproduced CI's LF content
and resolved that test-environment failure without changing the tokenizer.
No production change or live model inference was performed; the test runtime
is simulated.
