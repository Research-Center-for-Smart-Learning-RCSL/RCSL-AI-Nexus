# 2026-10-13

## Observe unavailable capabilities even while the host is quiet (#49, #50)

Stacked on PR #56, this change takes #49's unknown-observation routing fix and
the independently shippable availability work explicitly allowed by #50. PR #56
already covers #51/#52. #54 remains gated on recovery and a runtime quality
evaluation; #27 needs an operator-owned runtime/template comparison. The other
open issues are umbrella plans, a review watch list, or a parked feasibility
survey rather than additional implementation work for this branch.

Ollama routing now requires fresh positive residency and online node health.
The earlier `observed_state or state` expression treated a failed observation as
permission to trust a historical load, allowing a runtime restart to turn into
an implicit demand load. Observations older than 90 seconds, missing stamps,
future stamps and positive absence all refuse selection. MLX keeps its existing
fallback. Tests that previously only asserted load intent now explicitly set up
the observed residency needed to exercise their inference contracts.

The new admin-only availability endpoint reuses the selector and reports reason
classes without model aliases. The periodic reader also excludes adapters that
cannot be resolved and nodes blocked by durable uncertain operations. It runs
independently of the heartbeat so a hung probe cannot preserve a false green.
Its last successful timestamp makes a failed reader observable too.

Prometheus evaluates unavailable-capability, unresolved-operation, silent-outage
and stale-observer alerts. Delivery reuses the existing health job's Tier 1 mail
path. Durable usage/refusal rows define the silent-outage window; a process
restart does not reset it. No notification was sent during verification.

The [availability runbook](../runbooks/capability-availability.md) records the
contract, alert timing, tests, local Prometheus persistence check and remaining
production validation. Neither issue is closed: desired residency, bounded
automatic recovery, reset actions, residency-mismatch/reconcile metrics and the
production VM-restart check remain outstanding.
